## What the compiler can do that it could not

**Differentiability has a subject.** The pass reported 0 of 155 functions
differentiable, which was the corpus rather than the analysis: MAGE's numerical
surface is `net` / `layer` / `train`. It now covers all three.

```
$ scripts/measure-differentiability.sh

101 tracked .mg sources; 0 could not be parsed.

subject      total    diff  smooth    a.e. unknown     not
nets            34      34      19      15       0       0
trains           7       7       7       0       0       0
functions      155       0       0       0       1     154
```

Reported per subject and deliberately not merged: one ratio over all 196 would
be "41 of 196" and would answer neither question. The finding *is* that the two
populations differ.

**`grad(e, w)` is an expression.** `f slope(w: f64) -> f64 { grad(w * w * 3.0 +
w * 2.0, w) }` — `slope(4.0)` is `26.0`, exactly. Forward-mode dual numbers,
because the signature names one `w`. `∇(e, w)` works too, a spelling the sigil
table had been publishing for a construct that did not exist.

**The differentiability obligation is discharged where its evidence is.**
`types.rs` gives `grad` its type and deliberately does not check that `e` has a
derivative, because `diff(e)` is a property of the call graph — nothing in
`grad(noisy(w), w)` says `noisy` reaches a console. `differentiable.rs` owns
that premise. `NotDifferentiable` is an error naming the reason; `Unknown` is a
**warning**, because refusing a program the compiler merely failed to analyse
turns the absence of a verdict into a rejection.

**Two kinds of claim have different words.** `verdict.rs`: `Proved` /
`Evidenced { n }` / `Unspecified` / `Unreached { why }` / `Refuted { at }`,
borrowed from `../StatodynamicAnalysis` with the correspondence written out.
`Evidenced` cannot render without its sample count; `holds()` is false for both
absences; the summary names the coverage hole even when it is zero. No ordering
and no score, because both invite the collapse the module exists to prevent.

**`mage-parse --gradcheck`** supplies the inductive half against central
differences, and prints both verdicts side by side without merging them.

Three new commands — `--differentiable`, `--gradcheck`, and
`scripts/measure-differentiability.sh` — plus three new checkers:
`check-open-items.sh`, `check-ontology-types.sh`, and `find-mage-parse.sh` as a
shared resolver. Each of #27 and #29 takes the CI checker count from 17 to 18;
together they make 19.

## The findings, by shape

Grouped by shape rather than by file, because the shapes are what recur.

### An accurate statement about an empty subject, wearing a tick

Four of these, all in #26, and the pattern is identical every time: a count that
is correct, about a population nobody looked at, rendered as success.

* **`VerifyStatus::Trivial`** meant *nobody specified this*, and the reporter
  **skipped its rows** while the summary line counted them. `Contracts checked:
  2` for a module with one contract. The name was the defect: "trivial" reads as
  *it passed, easily*, and the renderer acted on that reading.
* **RAP `verify/contracts` answered `"ok": true` for it.** Worse in a
  machine-readable API than in prose, because prose gets read sceptically and a
  boolean does not.
* **RAP `capability/check` answered `"ok": true` for a module with no agents.**
  `.all()` on an empty iterator is `true`. **`.all()` is where this hides**: the
  emptiness is invisible at the call site and the line reads as "every one of
  them is verified". Found by sweeping the surface a *second* time, after the
  first fix.
* **`--pipeline` printed `✓ safety annotations stripped` on every file**, and
  nothing in the corpus has ever been elidable — the two files matching
  `grep unsafe` match it in comments.

**Five other RAP `ok` booleans were swept and deliberately left alone**, which
matters more than the fixes. The rule:

> Does `ok: true` claim a **property was established**, or report that **no
> violation was found**?

`language/parse`, `lint/check`, `effects/check` and `heal/graph` answer the
second, and vacuous truth is correct there. `doc/query` is
`!matches.is_empty()`, already correctly false when empty. Converting all of
them would have made the surface worse.

### One edit, many costumes

* **Seven scripts carried their own `BIN=prototype/target/release/mage-parse`.**
  A shared cargo `target-dir` sends builds elsewhere while a leftover
  `prototype/target/` keeps an old binary that is found first — three weeks old,
  here. CI never saw it: a fresh runner has neither.
* **And the fix missed three of them.** `check-doc-blocks.sh`,
  `check-doc-evals.sh` and `check-vocabulary.sh` run their real work inside a
  `python - <<'PY'` heredoc that opened with its *own* copy of the path, and a
  quoted heredoc does not expand `$BIN`. **A path inside a heredoc is a copy
  that does not look like one.** Found by running them, when a documentation
  block that typechecks was reported as failing.
* **`RAP endpoints | 24`** in `MAGE_ONTOLOGY.md`, whose §5 was corrected from 24
  to 38 on 2026-09-02 *with a note in the document recording the correction*.
  One copy fixed, the other eighty lines down left alone.

### Handled everywhere, produced nowhere

* **`Expr::UnsafeBlock` is handled by eight passes and constructed by none.**
  `unsafe { … }` is `expected expression, found KwUnsafe` in every position, and
  `MAGE_SPEC.md` documented it as accepted-and-elided in three places. It reads
  as implemented from both directions at once: the spec says yes and the code
  looks busy. `unsafe fn` — spelled `uf` — does parse and is elided correctly.
* **`autograd.rs`'s tape is never given anything to differentiate.**
  `build_tape_from_train` walks `TrainDef.body`; every `train` block is
  declarative, with `net:` and `loss:` as *typed fields*, and no `.mg` source
  writes a train `body` at all. The tape holds one node on all seven train
  blocks, and `--pipeline` reported `✓ train Learn: 1 forward ops, 1 backward
  ops` for each. Worse than empty: with one node, that node is both the loss and
  the parameter, so the seed `d(loss)/d(loss) = 1.0` is recorded in
  `param_grads` as the gradient of the loss with respect to the net.

  It had no symptom because training genuinely works — `--target=abl-train`
  reduces `train_demo.mg`'s loss by 99.95% — through `rmi`'s backend, which never
  touches this module; and `backward` emits MLIR **text** that nothing executes.

## Five mistakes of mine, and what each one teaches

Recorded because the shapes travel further than the fixes.

1. **The stale-binary sweep stopped one short**, and I said it was complete. Six
   copies found, three more hiding in heredocs. Finding six was the reason to
   look for the seventh.

2. **My first enum-count scan reported eleven disagreements. Four were false.**
   It resolved same-named enums across crates by taking the one with the most
   variants, comparing `ContractKind` in `forge.rs` against a row about
   `verify.rs`. **A checker that resolves an ambiguity by picking is a checker
   that invents findings.** The fix was to make the document say which enum it
   means and fail on an unannotated ambiguous row.

3. **Three of my scans returned three different counts for `TokenKind`** — 179,
   180, 182 — because doc comments, attributes and nested delimiters each break
   a naive line count differently. I did not publish a number until one
   algorithm could reproduce itself; otherwise I would have replaced six wrong
   figures with six differently wrong ones.

4. **I corrected `Effect kinds` from 16 to 18, and 18 is the wrong one of two
   readings.** The row means built-in effect kinds, which is **17**; the
   eighteenth `Effect` variant is `Custom(String)`, the representation of a
   *declared* effect block. Three documents already said seventeen and I had not
   asked them. Caught before merge. **A figure with two plausible readings needs
   the reading written down, not just the number fixed.**

5. **I repeated the autograd-tape claim in two pull request descriptions**,
   quoting `DIFFERENTIABILITY.md` without running it — the failure this
   repository is built to prevent, committed while extending the machinery that
   prevents it.

And two more, both small and both in this document's own subject. I twice
reported "seven PRs" when there are six. And **adding this file moved a pinned
count** — `root_docs`, stated in `DOCS.md` and `README.md` and measured by
`ls *.md` — so the first CI run on the pull request carrying it failed with
`documented as '24', measured '25'`. `HANDOFF.md`'s traps already record the
shape one construct over: *adding a MAGE block to documentation moves two
pinned counts*. Adding a **document** moves two more, and I did it while
writing the handoff about not doing that.

The mechanism worked exactly as built, which is the point of it: I did not
notice, and `check-doc-counts.sh` did.

Two more caught by tests rather than by me. My first gradient-check kink rule
asked whether the exact derivative matched the right-hand slope — which assumes
the answer it is checking — and called a *correct* derivative wrong for
`? w > 0.0 { w * 3.0 } : { 0.0 }` at zero. Finding it required adding `0.0` to
the sample set: **a sample set that avoids the hard point tests the easy half of
the design.** And my first autograd test asserted `param_grads.is_empty()` and
failed, which is how "worse than empty" surfaced.

## What was deliberately not built

Each of these is a decision, and the reason is the same one
`DIFFERENTIABILITY.md` used to keep tensor-product binding a specification:
**a construct with no caller is the mistake, not the missing construct.**

* **Reverse-mode `grad`, and `grad` over tensors.** I set out to build the first
  and stopped: `grad(loss, [w1..wn])` in `f` functions serves nothing in the
  corpus, and tensor `grad` is *refused* by the type checker rather than
  accepted into a program the evaluator cannot run — it has no tensor value at
  all.
* **The autograd tape's missing half.** Walking `NetDef.layers` into a tape
  would produce MLIR text that nothing consumes and nothing checks. The module
  is not touched; what changed is what gets said about it.
* **The other five RAP `ok` booleans**, per the rule above.
* **`Ontological concepts` and `Cross-domain relations`.** Neither has a stated
  counting rule — which subsections count, whether a relation counts once or
  once per direction — so a checker would invent the definition it then
  verifies, and go on to "catch" every future edit disagreeing with the
  invention. They print as NOT CHECKED on every run.

## Environment, for whoever runs this next

* **The cargo build lock is global on this machine.** `~/.cargo/config.toml`
  points every Rust project at one target directory, and other projects on this
  host regularly hold it — 39 concurrent `cargo` processes at one point, two of
  them mine. `test-all.sh --check-docs` could not complete locally on two
  occasions and CI was the check. Do not kill the processes; most are not yours.
* **Git checks files out CRLF here and the tools write LF.** That is why
  `check-skb-tree.sh` carries `--strip-trailing-cr`, why `check-ci-floors.sh`
  needed it (#28), and why regenerating `MAGE_ONTOLOGY.json` shows a whole-file
  diff until git normalises it.
* With #28, **all eighteen checkers pass locally on Windows.**
